# 项目运行台

一个 Windows 桌面工具，用来同时管理多个工作树或分支的本地开发进程。后端使用 Go，界面使用 Wails + WebView2。当前支持 Spring Boot（Maven/Gradle）和 Vue/Node 的 `package.json` 脚本。

## 直接使用

双击 `ProjectRunner.exe`。首次使用时点击“添加项目”，选择项目或工作树目录。工具会尝试识别 `pom.xml`、`build.gradle` / `build.gradle.kts` 和 `package.json`。显示名称默认取 Git 工作树根目录名；如果不是 Git 工作树，就取所选目录名。手动填写的名称不会被自动识别覆盖。然后在界面里填写端口、启动脚本或本地配置路径，保存并启动。

新增或复制配置时，后端端口取已保存后端配置的最大值加 1，前端端口取已保存配套前端及独立 Vue/Node 配置的最大值加 1；未运行的配置也参与计算，并跳过其他配置已使用的端口。没有对应历史时仍使用后端 `8080`、前端 `82`。生成后可手动修改，识别项目/前端不会覆盖已手动填写的端口；切换新配置的启动类型时，尚未修改的建议端口会随类型调整。达到端口上限 `65535` 时需手动选择可用端口。

新增项目选择目录后，会自动读取 `.run/*.run.xml`、`.idea/runConfigurations/*.xml` 和 `.idea/workspace.xml` 中的 Spring Boot、npm 运行配置，同名配置优先使用共享文件，忽略默认模板。唯一的后端和前端会自动配成一组；存在多个候选时可选择。自动导入保留已手动编辑的字段；已有项目可点击“从 IDEA 导入”选择配置重新填入表单，检查后保存才生效。

导入内容包括模块、JVM/应用参数、环境变量、端口、`application.config.path` 外部配置、前端目录及脚本；展开 `$PROJECT_DIR$` 等路径变量，从 IDEA 本机 SDK/Node 设置定位有效路径，构建工具优先使用项目 Wrapper，再尝试 IDEA 设置、已有配置和系统 PATH。已被其他配置使用的导入端口会重新建议，本机代理地址可自动跟随后端端口。无法解析或不存在的路径会显示提示。当前仍按模块的可执行 JAR 启动 Spring Boot，不导入 IDEA 的编译、安装依赖等“启动前”任务，也不修改 IDEA 文件。

- Maven 项目默认智能启动：首次启动、构建记录无效/升级、启动 JAR 缺失/无效/被替换时，从当前工作树根目录执行 `mvn -pl <启动模块> -am clean package -Dmaven.test.skip=true` 建立可信产物；源码或构建输入的一般变化执行增量 `package`，源码/资源删除或重命名执行 `clean package`；否则直接使用 JDK 运行已核验的当前工作树 JAR，跳过 Maven。无需手动 `install`，不会把项目模块覆盖到共享 `.m2` 中。旧配置自动使用此流程；Gradle 仍使用 `bootRun`。
- 检查内容覆盖显式声明的 Maven 模块的 POM、`src/main`（Java、资源等）、`.mvn`、Wrapper、构建工具/JDK、Maven settings/toolchains 及已识别的构建环境变量引用。按文件内容校验，新增、删除、重命名也会触发构建；前端文件、文档、`src/test`、端口、其他 JVM/应用参数和外部应用配置不触发构建。构建记录保存在工作树 `target/.project-runner/`，重开工具仍可复用；不直接信任尚未登记的旧 JAR。自定义目录/外部生成输入、外部 SNAPSHOT 依赖更新等场景请点击“重新构建”。
- 启动和重启都自动判断是否需要构建。源码或资源删除/重命名时自动清理后构建，避免残留旧文件；“重新构建”始终强制执行 `clean package`，成功后再启动。开发启动默认跳过测试，项目测试应单独运行。构建前检查 JAR 是否被其他运行实例占用，占用时提示先停止，避免覆盖运行中的产物。开始构建前撤销旧成功记录；构建失败、取消或构建期间输入有变化时不保存可复用记录，下一次会重新构建。
- Maven 后端复用 JAR 或增量构建后的初始化失败时，运行台用当前尝试的日志识别 Mapper 引用缺失类、明确的依赖 JAR 压缩损坏等产物异常。先撤销该产物的复用记录，待进程及子进程退出、端口释放、JAR 未被占用后，最多自动执行一次当前工作树的 `clean package` 并重新启动后端，前端保持运行。数据库/Redis 连接、端口、XML 语法、类静态初始化等错误不触发此恢复；运行中故障不自动重建，已执行过清理构建的产物再次失败也不循环重试。恢复可停止，重开运行台也不会复用已撤销记录的坏包。界面显示清理重建、再次启动、已自动恢复或恢复失败；日志标记尝试编号，原始失败和重试日志在现有缓存上限内保留，成功恢复后历史错误不会继续标成当前错误。构建复用记录版本升级后首次启动会清理一次，后续未变化仍直接启动 JAR。
- 界面先显示“检查中”，需要构建时显示“构建中”，随后进入“启动中”“运行中”；日志说明构建/复用的原因。构建失败不会启动旧 JAR，检查和构建阶段也可以停止；关闭窗口会终止构建和运行进程及其子进程。同一工作树同时只允许一个 Maven 构建/运行实例，不同工作树可独立运行。
- 选择包含多个 Maven 模块的根目录时，自动识别显式绑定 `repackage` 的启动模块；存在多个候选时手动选择“模块子目录”。选择模块目录也会向上定位包含它的聚合 POM，限定在当前 Git 工作树内。需要启动模块生成包含 `Main-Class` 的可执行 JAR，目前支持 `jar`，不支持 `war`。产物路径根据 POM 的 `build.directory`、`finalName` 和常用项目属性解析；复杂 profile 或外部父 POM 中定义的路径暂不自动解析，失败时会提示明确配置路径。
- 优先使用项目中的 `mvnw.cmd` / `gradlew.bat`；否则使用系统 PATH 中的 `mvn.cmd` / `gradle.bat`。也可以在界面中指定 Maven / Gradle 启动文件。
- 新增或编辑项目时，JDK 目录和 Maven / Gradle 启动文件旁的“复用”按钮可选取其他已保存项目的路径。启动文件只列出相同启动类型的项目；不会顺带复制项目目录、端口或本地配置。
- Spring Boot 端口会传给 JVM：`-Dserver.port=8081`。本地配置文件或目录会传成 `-Dapplication.config.path=...`，属性名可改。
- Vue/Node 选择 `package.json` 脚本与包管理器。Vite 和 Vue CLI 可由界面传入端口；其他脚本可选择 `PORT` 环境变量或“不传端口”。
- 一个后端搭配一个前端时，在后端配置中勾选“启用配套前端”，点击“识别配套前端”或选择含 `package.json` 的前端目录。自动识别只在所选 Git 工作树中向上查找常见目录（`ruoyi-ui`、`frontend`、`web`、`client`），优先选择 `dev:vite`，然后是 `dev`、`serve`、`start`。可分别指定 Node.js 目录和 npm / pnpm / yarn 启动文件；留空使用系统 PATH。
- 配套前端和后端是一条保存配置。顶部“全部启动”“全部停止”“全部重启”同时操作两端，后端构建和前端启动并行进行；“重新构建”会清理后端产物并重启整组。日志区可切换“后端”“前端”，各自显示状态、错误和日志，也能单独启停当前服务。一端失败时另一端继续运行，整组显示“部分运行”；“补齐启动”只启动未运行的一端。
- 前端位于后端项目目录内时，修改“项目 / 工作树目录”会实时更新前端路径，保留 `ruoyi-ui` 等相对位置；复制配置、手输路径和浏览选择都适用，前端端口、脚本、工具和环境变量保留。手动选择新的项目内目录会更新跟随位置，指定项目外目录则保持独立。新目录缺少前端 `package.json` 时保存会提示错误，请选择正确目录或点击“识别配套前端”；不会退回旧工作树的前端。
- 默认把后端地址传给前端环境变量 `VUE_APP_BASE_API_TARGET=http://localhost:<后端端口>`，前端端口额外传入小写 `port`。例如后端端口 `8082`、前端端口 `82`、脚本 `dev:vite`，等价于截图中的 IDEA npm 配置。代理变量名可修改，也可关闭自动代理并手动配置环境变量。前端代码需要读取该变量；运行台不修改 Vite/Vue CLI 的代理源码。自动代理和端口设置优先于同名手填变量。
- 启动整组之前检查两个端口，任何一个被占用时都不启动。已在运行的一端会保留；任一端运行时需先停止整组才能修改或删除配置。停止和关闭窗口会终止 npm/Vite 的子进程。前端依赖需已安装，运行台不自动执行 `npm install`。
- 多个配置可同时运行，日志各自展示并可搜索。“重点”默认显示错误、警告和运行状态，折叠普通信息与堆栈，并合并重复消息；“仅错误”和“全部”可随时切换。检测到错误会弹出一次提示，并在项目顶部保留提示条。日志内容仍会在当前运行中保留，直到达到缓存上限。
- 运行日志中的 HTTP/HTTPS 地址可直接点击，通过系统默认浏览器打开；支持本机、局域网、IPv6 和带查询参数的地址，保留原有日志颜色。也可用 Tab 聚焦链接后按 Enter 打开。
- 日志区域顶部的“Git 未提交”切换到当前选中服务目录所属工作树的只读 Git 视图，显示工作树根目录、分支（含分离 HEAD）、已暂存、未暂存、未跟踪及冲突文件。可搜索路径、手动刷新，点击文件查看工作区或已暂存差异；未跟踪文本显示内容，二进制文件仅显示状态，大文件预览限制为 1 MiB / 5000 行。支持独立 Git worktree 和子模块目录，忽略文件不列出；服务未启动、目录尚未保存时也可查看。不提供暂存、提交、回滚或切换分支操作，查询不会刷新写入索引，也不会执行外部 diff/textconv 或 fsmonitor 工具。
- 日志筛选按钮旁的“终端”打开内置 PowerShell 控制台。“＋ 新标签页”创建独立会话，点击标签切换，点击 `×` 关闭该终端及其子进程；点击“重点 / 仅错误 / 全部”返回运行日志。新终端默认在当前选中的前端或后端目录打开，继承该服务的环境变量和配置的 JDK、Node、构建工具路径；优先使用 PATH 中的 PowerShell 7，否则使用 Windows PowerShell。支持中文、交互式命令、`Ctrl+C` 中断和 `Ctrl+V` 粘贴；选中文字时 `Ctrl+C` 复制。切换项目或查看日志保留已打开会话，停止项目服务不关闭终端，删除配置或关闭运行台会清理对应终端。最多同时保留 16 个标签页，关闭运行台后不恢复会话。
- “终端”旁的“Codex 分析”在当前前端或后端目录新建 Codex CLI 标签页，自动带入该服务的启动类型、模块、脚本、端口、退出码和最近日志快照。默认通过当前 CLI 查询可用模型（单次查询最多 5 秒），配置模型可用且支持 `low` 时沿用，否则自动选择列表中支持 `low` 的首个可见模型；以 `low` 强度、`read-only` 沙箱分析，本次启动禁用 Hooks，避免钩子信任弹窗和沙箱外钩子执行；提示先定位异常链，必要时只查相关源码，简短输出根因、位置和解决建议，不修改代码、不构建或启动服务。可在终端继续追问；“▾”可选择模型和推理强度（读取当前 CLI 的模型列表，支持手输模型名），按项目记住选择，仅通过本次启动参数覆盖，不修改全局模型配置；模型列表读取失败时提示重试或手动指定，不沿用未经核验的默认模型。自定义提供商保留其配置模型。沿用本机 CLI 的登录、提供商和配置，需要 PATH 中已有 `codex.exe` 或 `codex.cmd`。没有日志时提示先复现错误；快照最多保留当前缓存最后 400 行 / 256 KiB，隐藏常见密码、Token 和 URL 凭据，不附整个环境变量或外部配置内容；快照在标签进程结束、关闭标签或运行台时清理。每次点击开启独立分析，日志快照在点击时固定；新一轮启动错误可再点击分析。CLI 初始化、登录提示和分析进度均在终端显示。
- 左侧项目列表可直接点击“启动”或“停止”操作对应项目；点击项目名称仍可切换到该项目的日志与配置。侧栏启动当前项目时会先保存尚未保存的修改。
- 左侧项目可上下拖动排序，拖动时蓝色线条标示插入位置；也可聚焦左侧拖动手柄后按 `Alt+↑ / ↓` 调整。顺序会自动保存，重新打开仍保留；修改名称不会重排，新建或复制的配置追加到列表末尾。运行中的项目也可调整顺序，拖动不会切换项目或启停服务。
- 项目卡片会显示本次启动计时；项目被判定为运行中后固定为启动耗时。停止后仍显示本次的耗时，关闭工具后不保存计时。
- 已保存项目默认只显示日志。顶部“配置”按钮可展开或收起配置表单；新增项目自动展开，保存后返回日志视图。展开时配置区和日志区分别滚动，也可拖动两者之间的分隔条调整日志高度；窗口重新打开后保留该高度。
- Maven、npm 等命令行进程在后台运行，不会弹出额外终端窗口。Windows 批处理文件通过 `cmd.exe` 启动，支持普通的空格、中文路径，无需改成 8.3 短路径。未保存的配置不会自动保留。

顶部“启动检查”集中展示前后端的目录、JDK / Node 和构建工具版本、外部配置、启动脚本、前端依赖与端口问题；启动入口也会先检查，发现问题时不启动。项目 Wrapper 不在检查时执行，避免触发下载；版本声明仅提示，复杂 Maven 父 POM、profile 或 Node engines 范围请结合项目要求判断。工具版本查询最多等待 2 秒，结果缓存 5 分钟。已运行的服务保留，启动只补齐缺失服务。

端口冲突会显示真实监听进程的名称和 PID（支持 IPv4 / IPv6）。属于运行台管理的进程树时，可跳转对应配置或停止该服务，然后重新检查；外部进程仅展示信息，由用户通过所属软件停止或修改端口。

配置中可选填本机 HTTP(S) 就绪地址、预期状态码和 5–600 秒等待时间；留空仍按端口监听判断，默认等待 90 秒。健康请求不使用系统代理、不跟随重定向。超时显示“未就绪”，进程保持运行，可查看日志、停止或重启；后台继续检查，后续就绪会自动恢复状态。勾选“前后端均就绪后自动打开页面”后，整组就绪时打开前端页面（独立项目打开自身端口），每次运行只打开一次。“不传端口”的脚本不自动打开页面。

配套前端可勾选“全部启动时，等待后端就绪后再启动前端”，减少后端构建或初始化期间的前端代理报错。默认仍同时启动；开启后，前端显示“等待后端就绪”，可单独停止等待或全部停止。后端启动失败或就绪超时不会启动前端；处理后端问题后点击“补齐启动”。如需先运行前端，可以取消等待后点击“启动当前服务”。此开关随项目和模板保存，后端就绪依据上面的健康地址或端口检查。

运行日志标题附近显示当前服务进程树的 CPU、内存和进程数量，包含运行台管理的 Maven、npm、Java 等子进程。界面可见且有运行中项目时每 2 秒采样；切换前后端可分别查看。CPU 按整台电脑的逻辑处理器数量归一化，第一次采样暂不显示百分比；内存为各进程工作集之和，共享内存可能重复计入，无法读取部分进程时显示“≥”。停止后隐藏资源信息，重启会重新采样。

侧栏“收起”可隐藏到 Windows 托盘，项目继续运行；点击托盘图标恢复窗口，右键选择“打开运行台”或“退出并停止所有项目”。“应用设置 / 更新”可启用“关闭窗口时收起到托盘”，默认关闭，保持原先关闭窗口就停止所有项目的行为。托盘不可用时窗口关闭仍退出，避免隐藏后无法找回；明确点击“退出”始终停止项目并退出。

“应用设置 / 更新”显示当前版本与源码提交，手动点击“检查更新”可查询本仓库的最新正式 GitHub Release，并打开发布页面查看说明和下载；不自动下载或替换运行中的程序。发布流程会把标签和提交号写入程序，普通源码构建显示“开发版”，不会把开发版当成旧版本建议覆盖。私有仓库优先通过本机已有的 GitHub CLI 登录查询，SSH 密钥本身不能用于 GitHub REST API；未登录或网络不可用时提示原因，仍可在已登录的浏览器打开 Release 页面。程序不读取或保存 GitHub Token，也不携带个人凭据，检查最多等待约 8 秒。

“依赖服务检查”可添加 MySQL、Redis 等名称、主机和端口，最多 16 项，无需账号密码。勾选“必需”时 TCP 连接失败会阻止启动或重启；未勾选的依赖只显示警告。每项连接等待最多 1 秒，同时检查最多 4 项。检查只验证 TCP 连通性，不验证认证、库表、协议或服务健康；不会启动或安装这些依赖。配套前端不重复检查后端依赖。

后端运行期间观察生产源码、资源和构建文件，Maven 覆盖显式声明的所有依赖模块，Gradle 覆盖工作目录内常规 `src/main` 与构建文件。发现更改后显示“后端代码已更新，需重启以应用更改”；点击“重启后端”会使用现有智能构建流程，配套前端保持运行。只做提示，不自动重启；恢复到启动前内容后提示会消失。每 3 秒检查文件元数据，对变化文件校验内容，每 30 秒完整校验一次，兼顾相同大小、还原时间戳的编辑。快照在检查构建缓存前取得，构建期间的编辑也会提示。忽略前端、测试和生成目录；自定义源码位置、外部配置及外部生成输入请自行重启或重新构建。读取失败或超过监测限制（20000 文件、单文件 32 MiB、合计 512 MiB）会提示检查不可用，不阻止运行。

编译日志中 Maven `文件.java:[行,列]`、javac `文件.java:行:列` 和 Kotlin `文件.kt: (行,列)` 等位置可点击，在 IDEA 打开当前工作树内的源码对应行。支持 Windows 路径、空格、中文和模块相对路径；简单文件名的堆栈位置仍保留为文本。IDEA 优先使用本机手动设置，否则尝试所选 IDEA 内置 Maven、PATH、正在运行的 IDEA 和标准安装目录。未找到时弹出“IDEA 跳转设置”，选择 `bin/idea64.exe`，也可从日志工具栏打开设置。使用 IDEA 官方的 [命令行文件定位参数](https://www.jetbrains.com/help/idea/opening-files-from-command-line.html)，打开文件前核验实际路径位于当前工作树；不会执行日志中的命令。IDEA 独立于运行台的进程管理。

日志工具栏的“启动历史”查看当前服务已结束的最近 10 次运行，重开工具仍可查看，并可复制脱敏日志。全局最多 50 条记录，每条最多 1000 行 / 256 KiB，单行最多约 8 KiB；超出部分保留末尾。落盘前清理 ANSI 控制符，隐藏常见密码、Bearer、URL 凭据、凭据前缀、敏感环境变量值及 PEM 私钥块。脱敏使用规则，任意业务数据仍可能保留；本机文件为普通 JSON，分享复制内容前可自行核对。历史不包含外部配置文件内容，也不会上传。

侧栏“配置模板 / 导入导出”可从当前配置保存本机模板，再为新工作树复用；项目目录重新选择，模块与配套前端保持相对位置，端口重新建议。本机模板保留本机工具、外部配置引用、环境与参数、依赖服务地址，最多 50 个 / 2 MiB。分享导出使用白名单，仅包含名称、启动类型、相对目录、端口、脚本等基础设置，剔除工具绝对路径、外部配置路径、全部环境变量、JVM / 应用参数、健康地址和依赖服务地址。导入文件先预览，再选目录应用到新表单，保存才生效；不会自动启动，也不覆盖已有配置。导入限制为 1 MiB / 20 个模板，绝对目录和向项目外跳转的相对目录会被拒绝。

运行错误会匹配本地提示卡，覆盖端口占用、JDK 不兼容、缺失类、源码编译错误、依赖解析、前端依赖、代理连接失败和就绪超时。提示来自当前运行尝试的日志，只展示证据和建议，不自动修复或执行命令；复杂错误仍可点击“Codex 分析”。

配置保存在 `%AppData%\ProjectRunner\projects.json`，当前服务日志最多缓存约 2500 行。启动历史、本机模板、IDEA 跳转设置、窗口关闭设置分别保存在同目录的 `run-history.json`、`templates.json`、`editor.json`、`desktop.json`；它们是本机运行数据，不进入源码包或 Release。使用 `PROJECT_RUNNER_CONFIG` 自定义配置路径时，这些数据跟随该路径的目录。

## 系统要求

Windows 10/11 x64，已安装 Microsoft Edge WebView2 Runtime；内置终端需要 Windows 10 1809 或更新版本（使用 [Windows ConPTY](https://learn.microsoft.com/en-us/windows/console/createpseudoconsole)）。运行 Spring Boot 需要项目所需版本的 JDK；运行 Vue/Node 项目需要 Node.js 和相应的 npm / pnpm / yarn。Maven / Gradle 项目应有 Wrapper，或提供可用的构建工具。

## 从源码构建

需要 Go 1.25+、Node.js/npm、Wails CLI v2.15.0。源码目录运行：

```powershell
go test ./...
wails build -clean -o ProjectRunner.exe
```

产物位于 `build\bin\ProjectRunner.exe`。

## 发布 GitHub Release

仓库提供 `.github/workflows/release.yml`。提交并推送代码后，再推送 `v主版本.次版本.修订版本` 标签即可自动发布：

```powershell
git tag -a v0.1.0 -m "ProjectRunner v0.1.0"
git push origin v0.1.0
```

请确认标签指向已推送、准备发布的提交；每个版本使用新标签。普通分支 push 不发布 Release。`v0.1.0-beta.1` 等带后缀的标签会标为预发布，不设为 Latest。

工作流在 Windows x64 环境中安装 `go.mod` 对应的 Wails CLI 和 Node.js 22，通过 `npm ci` 安装锁定依赖，重新生成绑定，执行前端测试、Go 测试、`go vet` 并打包。全部通过后，发布任务再次验证 SHA256，再创建 Release，附上 `ProjectRunner.exe` 和 `SHA256SUMS.txt`；说明包含运行要求、源码提交和 GitHub 自动生成的更新记录。已有同名 Release 时不会覆盖。

在 GitHub 的 Actions 页面选择 **Windows Release → Run workflow** 可以手动验证构建；手动运行仅保存构建附件，不创建 Release。构建附件保留 14 天。发布使用 GitHub Actions 自带的 `GITHUB_TOKEN`，无需上传本机 SSH 私钥或额外配置个人 Token。仓库需要启用 Actions，并允许本工作流使用的 GitHub 官方 Actions 和发布任务的 `contents: write` 权限。

本机也可用 PowerShell 7 执行相同测试与打包流程（不会上传或发布）：

```powershell
pwsh -File scripts/build-release.ps1 -Version v0.1.0
```

产物位于 `build\bin\release\`；Wails 不在 PATH 时可用 `-WailsExecutable` 指定 CLI 文件路径。下载程序的系统要求与上文一致，发布包不包含本机项目配置、日志、终端会话或业务项目文件。

## 当前范围

启动方式以本地开发为主，目前没有 Docker、SSH 或直接选择已有 JAR 的运行模式。Maven 启动流程自动构建并运行产物；停止、取消、构建失败、多工作树、前后端配对和 Windows 路径行为均有进程级回归测试。Vue 开发服务器保留自身的热更新能力。配置 JDK、构建工具和启动模块后即可使用；运行时仍需项目自己的数据库、Redis 等环境。
